# Accepting Command Line Arguments
We will start by creating the project with `cargo new`. We'll call the project `minigrep`.
```
$ cargo new minigrep
     Created binary (application) `minigrep` project
$ cd minigrep
```
The first task is to make minigrep accept 2 command line arguments: the file path and the string to search for. We want to run the program with `cargo run`, two hyphers to indicate the arguments are for the program and not `cargo`, and then the arguments:
```
$ cargo run -- searchstring example-filename.txt
```
Right now, the default program from `cargo new` cannot process given arguments, there are some existing libraries for this, but let's write it ourselves.

## Reading the Argument Values
To enable `minigrep` to read the values of command line arguments passed to it, we need the `std::env::args` function from the stdlib. This function returns an iterator of the command line arguments passed in. The key points of iterators are: They produce a series of values, and we can call the `collect` method to turn it into a collection such as a vector, which contains all the elements the iterator produces.

The following code allows `minigrep` to read any command line arguments passed in, and collect the values into a vector:
```rs
use std::env;

fn main() {
    let args: Vec<String> = env::args().collect();
    dbg!(args);
}
```
First, we bring `std::env` into scope with `use` so that we can use its `args` function. Note that we brought the parent module in scope rather than the function itself so we can use other `env` functions as needed. This is also less ambiguous since if we use `args` and call just `args`, it could be more easily mistaken for a function defined in the current module.

> ## The `args` Function and Invalid Unicode
> Note that `std::env::args` will panic if any argument contains invalid unicode. If your arguments contain invalid unicode, use `std::env::args_os` instead. This function returns an iterator that produces `OsString` values instead of `String` values. They are generally more complex to work with than `String` values.

On the first line of `main`, we call `env::args`, and immediately use `collect` to turn the iterator into a vector containing all the values produced by the iterator. We can use `collect` to create many kinds of collections, so we explicitly annotate the type of `args` to specify a vector of strings. `collect` is a function that often requires annotation.

Finally, we print the vector using the debug macro. Lets try this with no arguments and then two arguments:
```
$ cargo run
   Compiling minigrep v0.1.0 (file:///projects/minigrep)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.61s
     Running `target/debug/minigrep`
[src/main.rs:5:5] args = [
    "target/debug/minigrep",
]
```
```
$ cargo run -- needle haystack
   Compiling minigrep v0.1.0 (file:///projects/minigrep)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 1.57s
     Running `target/debug/minigrep needle haystack`
[src/main.rs:5:5] args = [
    "target/debug/minigrep",
    "needle",
    "haystack",
]
```
Notice that the first value in the vector is `"target/debug/minigrep"`, which is the name of our binary. This matches the behavior of the arguments list in C, letting programs use the name by which they were invoked in their execution. Its often convenient to have access to the program name in case you want it to be printed in messages, or change the behavior based on the command line alias used to invoke the program.

## Saving the Argument Values in Variables
The program is currently able to access the values specified as command line arguments. Now we need to save the values of the two arguments in variables so that we can use them throughout the rest of the program, as shown below:
```rs
use std::env;

fn main() {
    let args: Vec<String> = env::args().collect();

    let query = &args[1];
    let file_path = &args[2];

    println!("Searching for {query}");
    println!("In file {file_path}");
}
```
As we saw when we printed the vector, the program's name takes the first value in the vector at `args[0]`, so arguments start at index 1. The first argument in `minigrep` is the string we're searching for, so we put a reference in the variable `query`. The second argument is the file path, so a reference is placed in `file_path`.

We temporarily print these values to prove it works as intended, below is an example with the arguments `test` and `sample.txt`:
```
$ cargo run -- test sample.txt
   Compiling minigrep v0.1.0 (file:///projects/minigrep)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.0s
     Running `target/debug/minigrep test sample.txt`
Searching for test
In file sample.txt
```
Great, it works! The values are saved in the right variables. Later, we'll add some error handling for invalid arguments or lack thereof. Next, let's add file-reading capabilities.
