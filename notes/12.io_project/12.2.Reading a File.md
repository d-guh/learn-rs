# Reading a File
Now we'll add functionality to read the file specified in the `file_path` argument. First, we need a sample file to test it with: We'll use a file with a small amount of text over multiple lines with some repeated words. The following example has an Emily Dickinson poem that will work well! Create a file called `poem.txt` at the root level of your project, with the following content:
```txt
I'm nobody! Who are you?
Are you nobody, too?
Then there's a pair of us - don't tell!
They'd banish us, you know.

How dreary to be somebody!
How public, like a frog
To tell your name the livelong day
To an admiring bog!
```
With this in place, we will also edit the main.rs:
```rs
use std::env;
use std::fs;

fn main() {
    // --snip--
    println!("In file {file_path}");

    let contents = fs::read_to_string(file_path)
        .expect("Should have been able to read the file");

    println!("With text:\n{contents}");
}
```
First, we bring in a relevant part of the stdlib with `use`: We need `std::fs` to handle files.

In `main`, the new statement `fs::read_to_string` takes `file_path`, opens that file, and returns a value of type `std::io::Result<String>` that contains the file's contents.

After that, we add a temporary `println!` to print the value of `contents` after the file is read to check that it's working so far.

This code successfully read and printed the contents of the file. But, there are a few flaws. At the moment, `main` has multiple responsibilties. Generally, functions are clearer and easier to maintain if each function is responsible for only one task. The other problem is that we are not handling error as well as we could. Since the program is small it's not a large issue, but as it grows these problems would become harder to fix. It's a good practice to refactor early, since its much easier to do with smaller code.
